# ADR-002: Paths and Layout

Date: 2026-05-04
Status: proposed
Related Run: workspace-consolidation-2026-05

## Context

v4 needs path rules that are strict enough to protect public protocol, private
persona, generated adapters, and harness runtime state, but simple enough that
future agents can enforce them.

v3 used a 5+1 file-class taxonomy. v4 keeps the safety properties and removes
classes that described implementation flavor instead of ownership.

The layout must support public package source, private per-identity persona
data, project-local `.agents/` data, generated harness outputs, configure
time placeholder rendering, identity injection, and one symlink bridge.

## Decision

Use three file classes.

| Class | Definition | Examples | Render placeholders |
|---|---|---|---|
| Rendered file | Generated by `dotpanel configure` and managed by conflict rules | `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.kimi/AGENTS.md`, `~/.claude/settings.json`, `~/.codex/config.toml`, `~/.codex/model-catalog.gpt55-1m.json`, `~/.claude/skills/*/SKILL.md`, `~/.agents/skills/*/SKILL.md` | yes |
| Symlink | Explicit OS-level interface | `~/src/dotpanel/persona -> ~/.dotfiles/persona` | n/a |
| Source | Canonical authored content in dotpanel, dotfiles persona, or project `.agents/` | `protocol/skills/*.md`, `protocol/workspace.md`, `persona/voice.md` | varies |

Remove Wrapper and Runtime/harness-owned subclasses. Wrappers are rendered
files. Harness runtime protection is the explicit ADR-003 never-write list.

Public dotpanel layout:

```text
dotpanel/
  dotpanel/cli.py
  protocol/{workspace.md,skills/,rules/,reference/}
  harness/{claude/templates/,codex/templates/,kimi/templates/}
  bin/
  docs/{design/,adr/,architecture/}
  pyproject.toml
  persona -> ../../.dotfiles/persona
```

Private persona layout:

```text
~/.dotfiles/persona/
  voice.md
  identity.yaml
  rules/{index.md,interaction-triggers.md}
  reference/{operations.md,...}
```

Persona is **data only**: voice, identity, keyword-router rules, and
private reference. No runtime, no journal, no active-run index — those are
project-layer state under `{project}/.agents/`. Cross-project work that
doesn't fit one project goes to the operator's designated central-node
repo's `.agents/`.

Single operator per persona directory. No `<slug>/` indirection. A second
operator gets a separate persona directory (different dotfiles repo / path),
not a sibling subdirectory.

Project `.agents/` owns project conventions, handoffs, decisions, and
project-scoped memory.

`dotpanel root` returns the absolute package root using:

```python
Path(__file__).resolve().parents[1]
```

With `dotpanel/dotpanel/cli.py`, this returns the repository root in editable
installs. Shell utilities use `$(dotpanel root)`. Do not add `DOTPANEL_ROOT`.
`dotpanel doctor` verifies required directories under the reported root and
fails loudly on editable-install relocation problems.

Placeholders are rendered at configure time. The persona path is fixed at
`<dotpanel-root>/persona/` (a symlink); identity data comes from
`persona/identity.yaml`. Generated harness files receive concrete values,
not late-bound identity placeholders.

Wrappers reference persona through the bridge:

```text
$(dotpanel root)/persona/voice.md
```

`dotpanel init` creates and repairs the bridge symlink. Locked CLI signature:

```
dotpanel init [--persona-root <absolute-path>]
```

`--persona-root` overrides the default discovery (which checks `~/.dotfiles/persona/`). Without it, fresh operators on machines without dotfiles get a clear error message pointing at `--persona-root`. The flag is part of the locked public bootstrap interface.

## Alternatives Considered

| Option | Pros | Cons | Why rejected |
|--------|------|------|--------------|
| Keep v3 5+1 classes | More labels | Harder to teach; many labels do not change behavior | Ownership needs three classes |
| Separate runtime class | Makes runtime visible | Still needs explicit denylist | ADR-003 list is enforceable |
| `DOTPANEL_ROOT` env var | Easy shell access | Drift and hidden setup dependency | Root derives from code |
| `git rev-parse` root | Works in checkout | Fails for installed package | CLI root works in more contexts |
| `Path(__file__).parents[1]` | No env var; simple | Wheel installs need package data | Chosen with doctor guard |
| Copy persona into dotpanel | No symlink | Private stale copy near public repo | Rejected |
| Direct dotfiles paths in wrappers | No bridge | Exposes private repo layout | Bridge gives stable dotpanel-relative paths |

## Consequences

The model is enforceable: rendered targets follow configure conflict rules,
symlinks are rare interfaces, and source files stay owned by their repository.

Source files may be runtime-referenced by wrappers. This resolves the locked
decision ambiguity and keeps `CLAUDE.md` thin.

Root resolution creates a packaging requirement. Wheel installs must include
`protocol/`, `harness/`, and `bin/` under the reported root, or doctor must
fail.

Concrete packaging spec (for `pyproject.toml` + `MANIFEST.in`):

```toml
# pyproject.toml — single mechanism: include_package_data + MANIFEST.in
[tool.setuptools.packages.find]
where = ["."]
include = ["dotpanel*"]

[tool.setuptools]
include-package-data = true
```

```
# MANIFEST.in
recursive-include protocol *
recursive-include harness *
recursive-include bin *

# Persona symlink: persona is the symlink ENTRY, not a directory.
# `recursive-exclude persona *` only excludes files under it (which already aren't built).
# `prune persona` is the unambiguous "drop this entry, do not follow it" command.
prune persona
```

`dotpanel audit` (per ADR-3 Audit Surface) verifies the privacy boundary post-build by **opening the produced archive members directly**:

```python
# pseudocode
for archive in glob('dist/*.whl') + glob('dist/*.tar.gz'):
    members = list_members(archive)
    assert not any(m.startswith('persona') or '/persona/' in m for m in members), \
        f"PRIVACY VIOLATION: persona content in {archive}: {leaked}"
```

This catches the leak even if MANIFEST.in handling diverges across setuptools versions.

`dotpanel doctor` verifies install-time that:

- `$(dotpanel root)/protocol/` exists and contains `workspace.md`
- `$(dotpanel root)/harness/claude/templates/` exists
- `$(dotpanel root)/persona` either does not exist (fresh wheel install before `dotpanel init`) or is a symlink to a writable directory (after init)
- `$(dotpanel root)/persona/voice.md` and `$(dotpanel root)/persona/identity.yaml` exist (post-init)

The persona bridge is acceptable only if `.gitignore`, package manifests, and
doctor/audit checks prevent packaging or traversing the private target.

Editing `voice.md` does not require configure, because the wrapper reads it
at runtime.
