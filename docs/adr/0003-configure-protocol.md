# ADR-003: Configure Protocol

Date: 2026-05-04
Status: proposed
Related Run: workspace-consolidation-2026-05

## Context

`dotpanel configure` writes harness adapter files into directories that
also contain sessions, history, credentials, caches, plugins, and other
harness-owned data. It must regenerate managed adapters without damaging those
runtime paths.

v4 keeps marker-based generated-file safety, but replaces broad runtime
classification with exact never-write paths and a small configure protocol.

Configure must support fresh installs, cutover from old files, dry-run
validation during `dot pull`, sandbox output for tests, JSON files that cannot
carry comments, last-good adapter preservation, portable version gating, and
interruption-safe writes.

## Decision

Generated markdown and text files carry:

```text
<!-- Generated by dotpanel; do not edit directly. -->
```

Banner detection scans the first 10 lines so frontmatter can precede the
marker.

JSON files cannot carry comments. Managed JSON targets are declared in
`DOTPANEL_MANAGED_JSON`. Initial path:

```text
~/.claude/settings.json
```

Conflict handling:

| Existing target | Default behavior | With `--force` |
|---|---|---|
| Missing path | Create | Create |
| Recognized banner | Atomic overwrite | Atomic overwrite |
| `DOTPANEL_MANAGED_JSON` path | Overwrite only through configured JSON ownership | Overwrite |
| Non-banner text file | Fail validation | Overwrite |
| Symlink at rendered target | Fail unless expected migration target | Replace |
| Excluded runtime path | Never write | Never write |

`dotpanel configure --check` is a dry-run validator. It parses templates, resolves
placeholders, validates persona and referenced paths, validates target
legality, checks JSON path membership, includes `dotpanel doctor`, and reports
planned writes without mutating targets.

Exit codes:

| Exit | Meaning |
|---|---|
| 0 | success |
| 2 | validation failure |
| other non-zero | crash or unexpected failure |

Callers treat every non-zero as failure.

`dotpanel configure --force` permits cutover overwrite of pre-existing non-banner
files. It never overrides excluded paths.

`dotpanel configure --output-dir <path>` redirects harness output into a sandbox
for tests and migration rehearsal.

Writes are transactional per file:

1. Render and validate content in memory.
2. Write a temp file in the target directory.
3. Flush and close it.
4. Atomic move into place.

Multi-file all-or-nothing rollback is out of scope. Configure is deterministic
and rerunnable.

Configure never writes:

```text
~/.claude/{sessions,history.jsonl,projects,debug,cache,backups,file-history,ide,paste-cache,plugins,session-env,shell-snapshots,tasks,.credentials.json,.git,.gitignore}
~/.codex/{sessions,history.jsonl,*.sqlite,log,archived_sessions,shell_snapshots,vendor_imports,scheduled_tasks.lock,plugins,rules,memories,skills,installation_id,version.json,.personality_migration,.tmp,tmp}
~/.kimi/{sessions,logs,credentials,user-history,bin,config.toml,device_id,kimi.json,latest_version.txt}
```

Codex user-facing skill wrappers render to `~/.agents/skills/{name}/SKILL.md`
instead of `~/.codex/skills`, matching the official Codex user skill home.

A substrate-side `dot pull` (or any other sync wrapper) may invoke configure,
but `dotpanel` does not depend on the wrapper.

A sync wrapper declares `DOTPANEL_MIN_VERSION`, checks `dotpanel --version`,
and compares semver with POSIX-portable `awk`, not GNU `sort -V`.

`dot pull` runs `dotpanel configure --check`; if it passes, it runs real
configure. If it fails, it prints a prominent stderr warning, preserves
last-good adapters, and still exits 0. `dot pull --no-configure` skips the
version and configure steps.

## Alternatives Considered

| Option | Pros | Cons | Why rejected |
|--------|------|------|--------------|
| Always overwrite known paths | Simple | Can destroy credentials, history, plugins, or manual files | Too dangerous |
| Require marker for every managed file | Strong ownership proof | JSON cannot carry comments | Need `DOTPANEL_MANAGED_JSON` |
| Sidecar ownership metadata | Works for JSON | Sidecars drift and add cleanup burden | Path registry is simpler |
| Multi-file atomic configure | Strong rollback | Complex across dirs and harness roots | Per-file atomic is enough |
| Fail `dot pull` on configure failure | Automation sees it | Blocks dotfiles sync for adapter issues | Pull should succeed loudly |
| GNU `sort -V` version check | Short | Not portable to macOS | Use POSIX awk |
| Hidden test-only output dir | Smaller CLI | Migration needs same path | Public `--output-dir` stays |

## Audit Subcommand (locked decision)

In addition to `configure`, ADR-3 locks the `dotpanel audit` subcommand. Audit is
orthogonal to configure: configure validates a single render at install time,
audit enforces structural invariants for CI / pre-commit usage.

`dotpanel audit` returns 0 if all invariants below hold, 2 if any fail (with a
list of failures), and any other non-zero exit indicates a crash. Same exit
code conventions as configure.

## Audit Surface

`dotpanel audit` enforces invariants that go beyond what `configure --check`
verifies for a single render. v3's identity-isolation lint is gone (the
public/private boundary is structural now), but other invariants remain
worth catching automatically.

| Invariant | Failure example | Why it matters |
|---|---|---|
| Persona symlink target exists and is a directory | `~/src/dotpanel/persona` is dangling | configure would fail mysteriously; doctor catches install-time, audit catches drift |
| `persona/voice.md` and `persona/identity.yaml` exist at the (flat) persona root | persona-root has no `voice.md` after `dotpanel init` | configure would render a wrapper pointing at a missing file |
| `DOTPANEL_MANAGED_JSON` list is printable via `dotpanel audit` (or `configure --check`) | hidden state | operators must know which JSON files dotpanel owns |
| Generated files in harness homes carry the banner (or are in `DOTPANEL_MANAGED_JSON`) | banner stripped by user edit | next configure would abort with conflict; audit surfaces drift |
| Persona is excluded from any `dist/`, `build/`, or wheel artifacts | privacy regression in CI | catches packaging mistakes before publish |

`dotpanel audit` exits 0 if all invariants hold, 2 if any fail, with a list of
failures. Intended to run in pre-commit hooks and CI.

## Consequences

Generated ownership is inspectable for markdown and text. JSON ownership depends
on `DOTPANEL_MANAGED_JSON`, so `doctor` or `configure --check` should print that
list.

The never-write list is a data-preservation boundary and needs exact,
directory, and glob matcher tests, especially for `~/.codex/*.sqlite`.

`--force` is intentionally narrow: it helps cutover from old files and
symlinks, but it never writes excluded paths.

`dot pull` exit 0 preserves sync reliability but can hide adapter drift from
automation that watches only exit codes. The warning must be loud and include
the failed command and next manual check.

Per-file atomic writes prevent truncated files. They do not guarantee every
adapter file comes from the same run after a mid-run crash; rerun configure to
converge.

Follow-up work:

- test banner, JSON, symlink, non-banner, and excluded-path conflicts
- test POSIX awk semver cases in dotfiles
- ensure `--check` and real configure share one planner
- document that all non-zero configure exits are failures
